# ChatGPT → Open WebUI

Браузерная миграция чатов, вложений и персонализации из ChatGPT в аккаунт пользователя Open WebUI. Интеграция разворачивается отдельным сервисом рядом с Open WebUI. Менять файлы самого Open WebUI не требуется.

## Какие данные переносятся

| Из ChatGPT | В Open WebUI |
| --- | --- |
| Беседы, доступные экспортёру | Заголовки, видимые сообщения пользователя и ассистента, Markdown, ветки и выбранная ветка. Даты, закрепление и архивный статус сохраняются при наличии соответствующих полей в исходных данных. Имя исходной модели сохраняется как метаданные. |
| Файлы в сообщениях | Пользовательские вложения, изображения из сообщений и файлы из цитат с ID файла. Условия переноса и список распознаваемых форматов описаны ниже. |
| Сводка памяти | Каждый полученный раздел создаётся отдельной записью типа `context` в разделе **Сводка памяти**. |
| Пользовательские инструкции | Включённые инструкции создаются записью типа `user` в разделе **Пользовательские предпочтения**. |

Браузерная закладка запрашивает беседы и персонализацию. Список проектов она отдельно не выгружает. Серверный импортёр может создать приватные папки, если в полученных данных есть сведения о проектах и принадлежности чатов к ним.

Беседы, в которых после фильтрации не осталось видимых сообщений, пропускаются. Аккаунт, подписка, рабочие пространства, системный промпт и настройки ChatGPT не переносятся.

### Какие вложения поддерживаются

| Источник файла | Условие переноса |
| --- | --- |
| Файл, который пользователь приложил к сообщению | ChatGPT указал ID файла в метаданных сообщения. |
| Изображение в сообщении, включая сгенерированное | ChatGPT отдал `image_asset_pointer` со ссылкой `file-service://` или `sediment://` и файл удалось связать с сообщением. |
| Файл из цитаты | В метаданных цитаты есть `file_id`. Файл прикрепляется, если импортёр может связать его с видимым сообщением. |
| Файл, упомянутый ссылкой `sandbox:/mnt/data/…` или `attachment:…` | Импортёр заменяет ссылку на локальное вложение, если этот файл уже найден в выгрузке. Сама ссылка не запускает скачивание из ChatGPT. |

Если ChatGPT прислал имя без расширения, экспортёр может добавить его по MIME-типу:

| Категория | Расширения |
| --- | --- |
| Изображения | `.png`, `.jpg` (JPEG), `.gif`, `.webp`, `.svg` |
| Документы и таблицы | `.pdf`, `.docx`, `.xlsx` |
| Текст и данные | `.txt`, `.csv`, `.html`, `.json` |
| Архивы | `.zip` |

Для файла с расширением в имени экспортёр сохраняет исходный тип. Другие форматы, например `.pptx`, `.mp3` или `.mp4`, могут переноситься как обычные вложения по тем же правилам. Отображение превью зависит от Open WebUI. Файлы загружаются без индексации, одинаковое содержимое переиспользуется.

Файл попадёт в чат, если ChatGPT выдаст рабочую ссылку, файл удастся скачать и связать с сообщением, а Open WebUI примет его в пределах лимита. Внешние картинки по ссылкам и карточки поиска изображений отдельно не скачиваются. Отказы вроде `404` на запрос ссылки и ошибки привязки записываются в журнал миграции.

## Как это работает

1. Пользователь входит в ChatGPT и Open WebUI в одном браузере. На странице `/chatgpt-import/` перетаскивает **Выгрузить чаты в Open WebUI** на панель закладок. Если панель скрыта, её можно показать сочетанием `Ctrl+Shift+B`.
2. Пользователь запускает закладку во вкладке ChatGPT. Экспортёр собирает данные текущего аккаунта. После выгрузки пользователь нажимает **Открыть вкладку импорта**, затем **Импортировать**.
3. Браузер передаёт ZIP по частям. Сервис проверяет сессию Open WebUI и пишет данные через его API от имени пользователя. ZIP обрабатывается в памяти. В Open WebUI отдельно сохраняются чаты, связанные файлы и записи памяти.
4. В истории появляется приватный чат **Журнал миграции ChatGPT**. В нём указаны итог и причины пропусков по чатам, вложениям и памяти. Текст можно скопировать и передать администратору.

Если связь оборвётся, кнопка **Импортировать** в той же вкладке продолжит с неподтверждённой части. При новой миграции уже перенесённые чаты сверяются с сервером. Изменённые беседы отмечаются в отчёте, сохраняя текущую версию в Open WebUI.

## Требования

- Python **3.10+** на хосте сервиса. Сторонние Python-пакеты не нужны.
- Действующий Open WebUI. Локальный стенд проекта использует **0.13.4**.
- Активные сессии ChatGPT и Open WebUI. В Open WebUI пользователю нужны права на импорт чатов и, для переноса персонализации, доступ к памяти. Для создания папок нужны права на папки.
- Современный браузер с поддержкой закладок со скриптом и передачей данных между вкладками. Консоль разработчика и API-ключ пользователю не нужны.
- Для подключения пользователей по сети нужен HTTPS и прокси, который обслуживает Open WebUI и направляет `/chatgpt-import/` на сервис миграции с того же адреса. Для локального запуска можно использовать `127.0.0.1`.

## Развёртывание

### Локальный запуск на Windows

Установите Node.js, если его ещё нет, и используйте существующую установку Open WebUI с виртуальным окружением в `.venv`. Зависимости npm устанавливать не нужно. Запустите из папки проекта следующую команду PowerShell.

```powershell
.\start-local.ps1 -OpenWebUIRoot 'D:\Apps\Open WebUI'
```

Скрипт запускает Open WebUI, импортёр и локальный прокси. Open WebUI остаётся доступен на `http://127.0.0.1:3000/`, импорт — на `http://127.0.0.1:3000/chatgpt-import/`. Скрипт переносит существующий экземпляр Open WebUI на внутренний порт и использует его каталог данных. Для нестандартного расположения можно указать `-WebUIDataDir`, а для существующего журнала импорта — `-StateDir`.

После перехода на единый адрес замените ранее сохранённую закладку ссылкой с новой страницы импорта.

### Linux с существующим Open WebUI и Nginx

В пакете есть готовый сервис systemd и маршрут Nginx. Разместите checkout ветки `refactoring` в `/opt/chatgpt-exporter` и установите файлы запуска.

```sh
sudo install -m 644 deploy/chatgpt-import.service /etc/systemd/system/chatgpt-import.service
sudo install -m 644 deploy/chatgpt-import.env.example /etc/chatgpt-import.env
sudo install -m 644 deploy/chatgpt-import.nginx.conf /etc/nginx/chatgpt-import.conf
```

В `/etc/chatgpt-import.env` задайте `OPEN_WEBUI_UPSTREAM` — адрес существующего Open WebUI, и `OPEN_WEBUI_ORIGIN` — его публичный HTTPS-адрес. При необходимости настройте лимиты одного вложения и одной части выгрузки. Если меняете лимит части, согласуйте его с `client_max_body_size` во фрагменте Nginx.

Добавьте в существующий HTTPS-блок `server` для Open WebUI одну директиву.

```nginx
include /etc/nginx/chatgpt-import.conf;
```

Для `/chatgpt-import/` требуется стандартное поведение `Cross-Origin-Opener-Policy: unsafe-none`. Если прокси задаёт строгую политику глобально, исключите этот путь. После подключения маршрута запустите сервис и перечитайте конфигурацию Nginx.

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now chatgpt-import
sudo systemctl reload nginx
```

Пользователь открывает `https://webui.example.org/chatgpt-import/` на том же адресе, где входит в Open WebUI.
